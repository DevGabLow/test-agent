# Gherkin Feature Generator

## What This Skill Does
Generates comprehensive `.feature` files for Cucumber BDD testing, based on a Swagger analysis document. Produces scenarios in Portuguese with English Gherkin keywords.

## When to Use
- After Swagger analysis is complete
- Need to create feature files for API endpoint testing
- Converting API specs into executable BDD specifications
- Adding new features to an existing test suite

## Prerequisites
- `docs/swagger-analysis.md` must exist (generated by swagger-analyzer skill)
- Project structure must be scaffolded (from cucumber-project-scaffold skill)

## Procedure

### 1. Read Swagger Analysis
Read `docs/swagger-analysis.md` to get endpoint details, schemas, and scenario suggestions.

### 2. Group Endpoints by Tag
Each Swagger tag becomes a separate `.feature` file:
- `@pet` → `src/test/resources/features/pet.feature`
- `@store` → `src/test/resources/features/store.feature`
- `@user` → `src/test/resources/features/user.feature`

### 3. Generate Feature File Header
```gherkin
@{tag}
@regression
Feature: {Nome da Funcionalidade em Português}
  {Breve descrição do que a funcionalidade faz}

  Background:
    Given a URL base da API é "{baseUrl}"
```

**Mandatory rules**:
- First non-tag line MUST be `Feature: {Name}`
- Description after `Feature:` in Portuguese
- Background defines the base URL for all scenarios

### 4. Generate Scenarios per Endpoint

#### Happy Path (`@happy`)
```gherkin
@happy @ct0001
Scenario: CT0001 - Listar {recurso} com sucesso
  When envio uma requisição "GET" para "/{resource}"
  Then o status code da resposta deve ser 200
  And o array "{jsonPath}" deve ter tamanho maior que 0
```

#### Create (`@happy`)
```gherkin
@happy @ct0002
Scenario: CT0002 - Criar {recurso} com dados válidos
  Given eu tenha o payload:
    """json
    {
      "field": "value"
    }
    """
  When envio uma requisição "POST" para "/{resource}" com payload
  Then o status code da resposta deve ser 201
  And o campo "id" deve ser maior que 0
```

#### Negative (`@negative`)
```gherkin
@negative @ct0003
Scenario: CT0003 - Criar {recurso} sem campos obrigatórios
  Given eu tenha o payload:
    """json
    {}
    """
  When envio uma requisição "POST" para "/{resource}" com payload
  Then o status code da resposta deve ser 400
```

#### Boundary (`@boundary`)
```gherkin
@boundary @ct0004
Scenario: CT0004 - Criar {recurso} com nome vazio
  Given eu tenha o payload:
    """json
    { "name": "" }
    """
  When envio uma requisição "POST" para "/{resource}" com payload
  Then o status code da resposta deve ser 400
```

#### Auth (`@auth`)
```gherkin
@auth @ct0005
Scenario: CT0005 - Acessar endpoint protegido sem autenticação
  When envio uma requisição "GET" para "/{protected-resource}"
  Then o status code da resposta deve ser 401
```

### 5. Use Scenario Outline for Parametrized Tests
```gherkin
@happy @ct0006
Scenario Outline: CT0006 - Validar filtro por status
  When envio uma requisição "GET" para "/{resource}?status=<status>"
  Then o status code da resposta deve ser <expectedCode>

  Examples:
    | status     | expectedCode |
    | available  | 200          |
    | pending    | 200          |
    | sold       | 200          |
    | invalid    | 400          |
```

### 6. Scenario Grouping (Large Features)
For features with **15+ scenarios**, split into batches:
- **Lote A** (first file): `@happy` scenarios (~40%)
- **Lote B** (second file): `@negative` + `@boundary` (~50%)
- **Lote C** (third file): `@auth` scenarios (~10%)

### 7. DataTable Patterns

#### Headers (multiple unique name-value pairs)
```gherkin
Given eu tenha os headers:
  | name         | value            |
  | Content-Type | application/json |
  | api_key       | special-key      |
```

#### Form Params (may have duplicate names — use List<Map> in Java)
```gherkin
When envio uma requisição "POST" para "/pet/1" com form params
  | name   | value     |
  | name   | Bud       |
  | status | available |
```

### 8. Validate
- [ ] Every `.feature` starts with `Feature:` line
- [ ] Keywords in English, descriptions in Portuguese
- [ ] Tags follow `@{tag}`, `@happy`, `@negative`, `@boundary`, `@auth`, `@regression`, `@ctXXXX`
- [ ] No duplicate scenario IDs across the project
- [ ] DataTables are on the correct step (no arity mismatch risk)
- [ ] Background has base URL

## Output
Save each feature file to `src/test/resources/features/{tag}.feature`.
